# 專案架構

## 使用者流程

`首頁校區選擇 → 校區 3D 微縮模型 → 公共藝術配對遊戲 → 回饋表單`

每次只建立使用者選定校區的詳細 Three.js 場景；離開校區時會釋放場景資源，避免五個模型同時佔用瀏覽器記憶體。

## 主要目錄

| 目錄 | 職責 |
| --- | --- |
| `app/` | React 頁面、共用介面與校區路由流程。 |
| `app/scene/` | Three.js 模型、日夜燈光、鏡頭控制與校園動畫。 |
| `public/` | 網站公開圖片、遊戲素材與品牌檔案。 |
| `tests/` | 模型邊界、互動、效能預算與遊戲流程回歸測試。 |
| `worker/` | 正式環境的 Worker 入口。 |
| `docs/` | 產品規格、架構與維護文件。 |
| `.github/` | GitHub 自動檢查設定。 |

## 場景責任分層

- `app/scene/*-model.ts`：建立各校區幾何、材質與可釋放資源。
- `app/scene/*-life.ts`：處理學生、車輛、船舶、植栽等循環動畫。
- `app/scene/*-scene.ts`：整合相機、輸入控制、日夜過渡與渲染生命週期。
- `app/page.tsx`：控制校區選擇、操作列與遊戲切換。

## 維護原則

- 新增校區模型時，維持「模型建立、生活動畫、場景控制」分層。
- 不要把 Token、環境變數或使用者資料提交到 Git。
- 修改互動或模型後，先執行 `npm test` 再提交。
- `dist/`、`node_modules/` 與開發快取皆由 `.gitignore` 排除。
