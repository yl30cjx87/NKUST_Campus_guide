# 高科生力軍｜五校區藝術探索－產品規則

## 1. 產品定位

本產品是國立高雄科技大學五校區的互動式公共藝術探索網站。使用者先在輕量 3D 校區地圖選擇校區，觀看該校區的微縮模型，再進入公共藝術配對遊戲。

核心體驗順序固定為：

1. 五校區選擇
2. 單一校區 3D 展示
3. 進入該校區公共藝術遊戲
4. 在地圖上選擇作品位置
5. 作答正確後閱讀作品介紹

## 2. 使用對象與裝置

- 主要對象：高科大學生、訪客、校園導覽活動參與者。
- 主要裝置：手機；同時支援桌面瀏覽器。
- 手機進入體驗時以橫式為主要遊玩方式，仍需處理直式與安全區域。
- 不要求登入，不收集帳號、密碼或個人資料。

## 3. 五校區入口規則

- 首頁必須顯示：建工、楠梓、第一、燕巢、旗津五個校區。
- 首頁使用原生 Three.js 輕量 3D 地圖，不使用一張圖片代替整個入口地圖。
- 每個入口只顯示校區名稱，不顯示「進入 3D」或校區副標。
- 點擊模型才算選擇；拖曳、縮放與多指操作不得誤觸校區。
- 一次只載入一個詳細校區，進入後不得同時顯示其他校區或漂浮小島。
- 返回選單需直接回到五校區首頁。

## 4. 校區 3D 展示共用規則

- 所有主要模型建立在同一個正方形微縮底座與同一個 `Group` 內。
- 拖曳時旋轉模型本身，太陽保持世界座標方向，陰影隨模型角度自然變化。
- 支援滑鼠拖曳、觸控拖曳、滾輪或雙指縮放、上下傾斜與重設視角。
- 預設鏡頭為約 35～40 度俯視，完整呈現校區主要辨識物。
- 場景操作列只保留：返回選單、日夜切換、重設視角、進入遊戲。
- 手機操作列不得遮住主模型，並需保留系統安全區域。
- 建工與旗津為已完成的特色模型；楠梓、第一、燕巢目前可使用簡化模型，後續依照片逐一替換。

## 5. 日夜模式規則

- 白天與夜晚共用同一套模型，不重新建立場景。
- 每次進入校區預設為白天。
- 白天停留 8 秒後，自動執行一次白天轉夜晚，完成後保持夜晚。
- 日夜過渡約 1.6 秒，不得瞬間切黑。
- 手動日夜按鈕永久保留，且必須與自動切換共用同一套過渡。
- 手動切換不得重複建立計時器、燈光或模型。
- 夜晚約 30～40% 窗戶亮燈，應以房間或區域分組，避免規則棋盤或全部亮起。
- 夜晚保留冷色環境光，並以入口、警衛室、碼頭、路燈與船燈形成暖色局部光。

## 6. 建工校區故事規則

- 不大幅改動既有主建築、校名牆、警衛室、NKUST 景觀、道路與棕櫚樹配置。
- 白天須讓主要循環車輛在 8 秒切夜前完成進校。
- 車輛到柵欄前需減速、停車、等待柵欄抬起，再駛入校園。
- 夜晚時車輛再由校內駛出，柵欄完成第二次開合。
- 人物與腳踏車只作為少量生活元素，不得形成擁擠車流。

## 7. 旗津校區故事規則

- 不大幅改動既有主建築、碼頭、水面與船隻構圖。
- 白天 3～5 名學生由不同位置、不同時間走向主入口；人物需真正進入口後才隱藏。
- 白天不得出現釣魚活動。
- 夜晚學生需先從入口走出，再分流至散步、看海與釣魚位置，不得瞬移到碼頭。
- 至少一名釣客需完整表現：走到岸邊、拋竿、浮標等待、咬鉤、收竿、魚離水、濺水、收魚、重新開始。
- 第二名釣客可使用簡化循環，但不得與第一名完全同步。
- 白天波浪比夜晚明顯；夜晚以較平緩波浪、燈光反射與船燈營造氣氛。
- 船隻持續小幅浮動、晃動與形成尾波，不使用真實流體物理。

## 8. 公共藝術遊戲規則

- 先在校區地圖上點擊作品目標，再開啟答案選項。
- 答案選項必須保留在地圖範圍內，不用固定大型任務卡遮住地圖。
- 未點擊目標前不得直接顯示答案面板。
- 答錯時保留作答機會，不提前顯示作品介紹。
- 答對後關閉答案選項，再顯示作品圖片、尋寶提示與作品介紹。
- 作品圖片是主要內容，必須完整顯示並提供可關閉的大圖檢視，不得使用過度裁切縮圖。
- 已完成的作品可再次點擊查看介紹，不應重新強迫作答。
- 答案順序可隨機，但正確答案判定必須依作品 ID，不得依固定索引。
- 重新整理或重開遊戲時可重新隨機；同一次作答面板開啟期間順序不得跳動。
- 橫式與直式玩法一致，只調整空間配置，不改變操作順序。

## 9. 視覺與內容規則

- 主風格：精緻三渲二、日系動畫感、建築微縮模型。
- 禁止 Minecraft、方塊樹、極端 low-poly、玩具積木比例與過度鮮豔配色。
- 校區主建築、入口、道路與代表景觀優先於雜物細節。
- 公共藝術名稱、圖片、提示與介紹必須對應正確校區與作品。
- 新增內容需使用繁體中文；程式識別字與檔名維持 ASCII。

## 10. 效能規則

- 手機即時 WebGL 流暢度優先於看不到的細節。
- 重複窗戶、灌木、波紋與小物件優先使用 `InstancedMesh` 或共用 Geometry/Material。
- 只讓主建築、主要樹木與關鍵物件投射陰影。
- 像素比上限維持在 1.5 左右。
- 不使用 SSR、SSAO、Bloom、FFT Ocean、ray marching 體積光或真實流體模擬。
- 透明平面、Shader 與 Points 必須控制數量，避免多層透明大量疊加。
- 每次修改 3D 場景後至少驗證桌面、手機直式、手機橫式與非空白 Canvas。

## 11. 開發與驗收規則

- 不重做已正常運作的功能；修改需與既有架構整合。
- 建工與旗津的特色模型不得因製作其他校區而被替換或退化。
- 所有場景需在離開校區時清理動畫、事件、Geometry、Material 與 Texture。
- 修改後執行 `npm test`；所有測試通過才可交付。
- 發布前確認首頁五校區、各校區返回、日夜切換、重設視角、進入遊戲與作答流程。
- Git 密碼、Token、`.env`、瀏覽器帳密與本機快取不得放入交接壓縮檔。

## 12. 換機啟動

需求：Node.js 22.13.0 以上版本。

```bash
npm install
npm run dev
```

瀏覽器開啟終端機顯示的本機網址，通常為 `http://localhost:3000/`。

交付前完整驗證：

```bash
npm test
```
